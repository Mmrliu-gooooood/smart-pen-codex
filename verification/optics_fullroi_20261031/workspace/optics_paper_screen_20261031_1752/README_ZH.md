## 可立即用于排除错误推理的结果

1. 活动软件的 16 px 最小输入尺寸不意味着能装下可解码码窗；仍要求完整观测 6×6 和至少36点。
2. 当前活动应用使用无 prior 的正交冷搜索：x 点距8–32 px、轴比0.6–1.4；不是一般透视解码器。V3改善连续拟合但仍为未集成的独立研究；V4 NOT_ADOPTED，不能用其能力替当前产品背书。
3. 同样的像素尺度下，活动256 ROI与V3中央96 crop具有不同完整窗口空间。零拷贝crop不改变像素/毫米；全VGA FOV不能直接代换中央crop FOV。
4. 本研究7200组合中，256窗口筛查551个保留、829个有工程代理风险、5637个不满足本筛选合同、183个假设码窗穿过相机平面。换为96窗口，仅285保留；80窗口仅77。**这些不是decoder成功率**，筛选计数不用于估计实际设计概率。

```sh

python -O -m unittest -v
python sweep.py
python compare_crops.py
```

在新可写副本运行；保留冻结artifact字节。`sweep.csv`全部组合/原因，`summary.json`汇总，`crop_comparison.json`分窗比较，`verification/`测试日志。模型测试先红后绿，另有解析数值与有限差分Jacobian回归。Python模型无原生内存访问；不声称ASan/硬件或SDK验证。

## 模型、变量与筛选解释

详见 [MODEL_CONTRACT.md](MODEL_CONTRACT.md) 和 [SOURCE_FACTS.md](SOURCE_FACTS.md)。`screen_reasons`是本保守筛选合同不满足，并非运行decoder证明的拒绝：尤其外包矩形越界、最坏相向位移重叠可能对某个实际码字过保守；冷搜索标称尺度不保证实际拟合结果。`engineering_proxy_rejects`明确是可替换工程假设，不是源码阈值。只有真正调用decoder的独立结果可称代码接受/拒绝。

## 未解决的实物门槛

焦距像素参数需由真实近焦内参确定，不能自动用标称EFL/像元尺寸代替。缺镜头对焦范围/MTF/畸变、模块尺寸、近尖轴向/法向高度与镜头前端物距、笔芯遮挡、真实曝光/滚动读出、光照/SNR、印刷扩散/材料和IR响应。没有这些信息，不能从任一保留点冻结纸型或宣布笔尖精度。
