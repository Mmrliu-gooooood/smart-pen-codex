# IMU I²C 10k 上拉：起始测试频率与总电容预算

**尚无总线实测资格；本文件不授权给未完成板上电。** 当前 R501/R502 均为10k 1%，三信号块仍在布局，不能默认400kHz可用。首轮受控台架配置建议仅从 **100kHz** 开始，仍须量波形和验证通信；不是说100kHz无条件合格，也不修改当前固件/源。

## 官方依据与计算

[NXP UM10204 Rev.7.0（2021-10-01），Table 11 / §7.1](https://www.nxp.com/docs/en/user-guide/UM10204.pdf) 给出Standard/Fast的上升时间约束及RC拉升模型。按30%→70%阈值，`tr=ln(0.7/0.3)×Rp×Cb ≈0.8473RpCb`；100kHz对应最大1000ns，400kHz对应300ns。Cb是每根网的**总**电容，包括器件引脚、所有铜/过孔/连接和测量探头，不是只看走线长度。

按10k的初始+1%算10.1k（尚未加TCR/老化），计算上限：

| 模式 | tr上限 | 总Cb理论上限 |
|---|---:|---:|
| 100kHz | 1000ns | 116.85pF |
| 400kHz | 300ns | 35.06pF |

`calculate.py` 使用精确对数，normal/-O输出相同。比如100pF在此模型下约855.8ns：这不是实际板电容，也不代表满足其余时序。真正允许电容还需扣器件/电阻温漂老化、板材/制造及测量不确定度；这里没有凭空填一个已知总C或假设每毫米电容。

[ST LIS2DW12 DS11811 Rev.9，Table 7、§6.1](https://www.st.com/resource/en/datasheet/lis2dw12.pdf)列出100/400kHz接口时序并要求外部上拉；表7数值注明基于标准协议要求，非生产逐件测试。最终还须核MCU实际控制器配置及双方阈值/低电平、SCL高低时间、建立保持/ACK与容差，而非只比较一个RC式。

## 台架验收与开放门

分别在SCL、SDA两端测30%→70%上升、下降、VOL/VOH、振铃与过冲，并记录探头电容/接地方式；测试传感器应答、连续读写、低功耗进入/唤醒、供电边界和相机/无线活动干扰。若100kHz仍不满足标准时序，不可仅靠降频把超标上升沿称作合格；需重核实际电容、驱动和上拉值/功耗/灌电流，任何改料都要源/BOM版本化。

IRQ是单独数字中断，不能套I²C RC上拉预算。当前约117mm路径不是靠某个武断长度阈值判死刑，也不能因低触发频率忽略边沿、参考地/串扰、唤醒极性及重复唤醒测试。只保留测量门，不宣称已恢复首笔或姿态精度。
