# 点阵笔采样链路与倾斜模型核查（2026-10-30）

**结论：当前合成台架通过不等于相机接入后通过。必须先冻结“传感器原始像素 → 软件 ROI → 解码内部 ROI”的实际采样倍率；当前 V3 也未覆盖真实倾斜投影。** 本报告只读核查冻结代码，未改固件、SDK、相机 profile、PCB 或私人证据，未上传/采购/通电。

## 1. 200 像素究竟是什么

- 合成 renderer **直接生成200×200**，点距 `p=60/fov`，对应 .3mm 点距、声明的200像素宽纸面FOV；它不从640×480缩放，也不模拟传感器硬件裁切。[S1:15–24,35–42]
- 相机 V2 则只接受640×480 Gray8、307200字节；`pen_capture_app_roi`仅移动指针，保留stride640，**没有缩放**。允许96..256像素的子视图；必须保存全幅原点。[S2:5–7,14–29]
- 解码 V3 不会使用整个200视图搜索任意位置：先截正中96×96，若点过多才改80×80，要求36..100点；检测失败不会自动扩大窗口。[S3:59–77]
- 光学决策原文按**连续200传感器像素**做6mm估算，理论上与上述裁切一致；但其“5–7mm有效视野”实验描述若被当成完整VGA视野就会失配。它不是现有镜头已经达到该倍率的证明。[S4:“可复算…预算”及“最低成本物理实验”]

下表仅限正视、畸变忽略、均匀倍率；斜视应使用局部投影/标定而非单一全幅FOV：

|200px纸面宽|点距px|位移px = 半径px|相同倍率全VGA纸面宽|96px纸面宽|80px纸面宽|
|---|---:|---:|---:|---:|---:|
|5mm|12|2|16mm|2.4mm|2mm|
|6mm|10|1.6667|19.2mm|2.88mm|2.4mm|
|7mm|8.5714|1.4286|22.4mm|3.36mm|2.8mm|

**反例：若完整640px恰好看6mm，200px零拷贝子图只看1.875mm；内部96px只看.9mm（点距32px），80px仅.75mm。连6×6网格中心的1.5mm跨度都放不下。把输入从200扩到256也不解决内部固定96/80问题。**

全VGA缩至宽200会改变采样与滤波；保持4:3是200×150，不是200×200。拉伸至正方形又引入非等比倍率；完整方形裁切后缩放也不同于现有零拷贝。若将来选择重采样路线，必须单独实现、冻结滤波/映射/耗时与重新验收，不能借现有测试证明。

## 2. 六行六列究竟需要多大区域

Profile C为点距.3mm、四向位移.05mm、半径.05mm；对应 renderer 每个cell位移/半径均1/6。[S1:31–40]

- 六个**名义中心**跨度为5×.3=1.5mm，不是6×.3。
- 包含四向位移及完整墨点的保守轴向外包跨度为 `5*.3+2*(.05+.05)=1.7mm`。这是固定窗口的最坏支持界，不是任意位置一定能解码的保证。
- 还须给点阵相位、边缘剔除、旋转、透视与打印/成像留余量。正视未旋转时，在上述支持界上再留一个.3mm相位周期约为2mm；真实算法边缘规则/墨迹/纸边仍可能拒绝。旋转窗口的轴对齐包围盒也会增大。
- 6mm/200px时1.7mm支持约56.67px，因此96px通常有几何余量；全VGA=6mm时则约181.33px，绝非内部96px可容纳。

这里给出的是**所需采样倍率**，不是镜头选型已完成。仍缺实际模组/镜头在每档距离和姿态的原始标尺图、畸变、对焦范围与有效可解区域。镜头前端工作距离不等于主平面物距；不能从占位焦距/壳体图推出实际视场。当前使用者实际SC035HGS也不是本SC031GS驱动候选的已支持设备。[S4；S5]

## 3. 倾角模型：小规模可复现反例

V3只拟合**正交、可非等比仿射基**，没有一般剪切或投影分母；限定pitch8..32px、ratio.6..1.4、平面旋转±60°。[S6:192–225；S7] 平面内旋转30/45/60°不等于笔倾斜，更不等于相机光轴相对纸面法线的倾角。

本轮复用冻结 renderer 的真实逆单应栅格化，未改解码器。设理想针孔相机焦距400像素，光轴交纸中心距离Z=12mm，纸面点距P=.3mm，中心横向点距10px；纸面绕X轴旋转θ：

`camera(X,Y)=(X, Y*cosθ, Z+Y*sinθ)`，所以 `ratio=cosθ`、`perspective_y=P*sinθ/Z`。

这是**人为规定的可复算理想相机**，不是既有镜头标称/测量；无镜头畸变、失焦、噪声、运动模糊或墨迹。θ从纸面法线量，相机与笔杆安装角未知，不能直接转换为用户握笔角。`fov=6`在此仅表示未倾斜参考尺度/中央横向尺度，不表示斜视四边仍是6mm正方形。

使用真实冻结上游点阵，两种纸面相位（0、17），共8例：

|相机光轴倾斜θ|两例结果|解释|
|---|---|---|
|0°|2/2正确通过；最大网格映射误差约.073/.086px|仅理想正视合成结果|
|30°|2/2返回NO_GRID(-3)|当前模型/搜索未接受该投影|
|45°|2/2返回DETECTION(-2)|检测/ROI策略拒绝；没有证明仅因投影拟合|
|60°|2/2返回DETECTION(-2)|同上；中央ratio=.5也已超当前模型范围|

各例完整点阵支持窗口数量见`results.json`中`oracle_complete_windows_4px_guard`；它在96/80候选框中用四像素保护带及投影墨点外包四角检查，完全独立于解码。这个oracle只用于诊断，不输入解码器。拒绝原因不能一律归咎“视野没有6×6”；也不能凭8例推算成功率或总体不可能性。所有失败保持输出不变（冻结evaluate中的断言）。

真实倾斜还会使短轴点直径缩小、位置相关尺度变化，任意纸面/相机方位可引入非正交基；离轴视区尤其如此。以中心10px点距为例，60°理想投影中央短轴点直径仅约1.67px，而位移仅约.83px。光学/栅格/阈值误差不能用“全局快门”消除。本轮不增加巨大透视算法，更不以放宽门限换取假成功。

## 4. 按优先级应关闭的集成门槛

1. **采样合同**：明确原始VGA、200传感器裁切还是重采样；记录全幅/ROI原点、实际像素点距、有效6×6支持。将正视/倾斜标尺RAW加入固定测试集。不能把全幅6mm套进200px测试。
2. **姿态定义**：记录笔轴对纸面角、相机光轴对法线角、安装偏角和纸面方位；原始图必须覆盖实际安装几何，而非仅二维旋转。
3. **光学与算法共同门槛**：实测支持窗、像素短轴/长轴、点位移SNR、失焦与墨迹；再决定现有受限模型是否足够或需真正投影模型。必须检查拒绝率与错误接受，不能只展示个别好图。
4. **坐标意义**：ROI译回完整传感器坐标、半像素约定、镜头/笔尖姿态标定和压力/曝光时序必须统一。正确解出页上窗口不等于笔尖坐标准确。
5. **硬件前置**：SC031模式/寄存器与用户SC035不得互用；真实电平/pinout/供电与驱动资格仍独立冻结。不要为本诊断通电未知模组，不发布生产或准确度资格。
