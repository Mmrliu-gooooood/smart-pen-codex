### 2.2 GPIO/DVP与2MB内存：可行性初筛，绝非放行

`checked_comparisons.json`从原生102源抽取U101：**33个已连接GPIO，含4个strap，全部可映射到MINI N4R2**。GPIO26被MINI内PSRAM占用，不能用；GPIO33–37形成5个额外候选，相较PICO-N8R8这5脚不能复用。完整逐网映射在JSON；boot/eFuse/电平/复用时序仍需重审。相机D0–7用GPIO7–14，PCLK/VSYNC/HREF为15/16/17，XCLK38；USB19/20保留。这只是资源可达，不是布通/信号完整性通过。

MINI相机控制器仍公开≤40MHz 8–16bit DVP，与现S3相同；模块不会修复旧72MHz相机配置。现1.8V相机接口转换和所有掉电隔离需求不消失，参见[本地DVP时序预算](../../electronics/DVP_TIMING_BUDGET_20261028.md)。

本地`smart_pen_continuous_v3_target_benchmark_20261029/main/bench_main.c:13,38–39`直接给出200×200灰度图40000B及连续decoder workspace32640B：单图+workspace **72640B**，两图+workspace **112640B**。因此“2MB一定不够”没有依据；同样这不是SDK完整堆/吞吐预算。该benchmark明确CPU-only、未驱动相机/无线/存储，且当前将两块放内部RAM；不能把全部PSRAM当可用内部DMA内存。

[Espressif camera官方组件2.1.8](https://components.espressif.com/components/espressif/esp32-camera/versions/2.1.8/readme?language=en)提醒原始格式PSRAM吞吐、无线并行及多buffer约束；PSRAM DMA需配置，默认关闭。对本项目必须测：实际传感器是否原生ROI或先整帧再裁、DMA内部描述符/缓冲、PSRAM DMA支持/缓存一致性、灰度数据完整性、双buffer并发、decoder堆栈/峰值、BLE/Flash任务和丢帧诊断。200×200×fps只作平均负载，不能替代瞬时PCLK和服务延迟验证。

4MB Flash也不因旧“2×2MB OTA+4MB记录”分区就必然淘汰；应重算boot/NVS/两个实际固件槽/必要记录容量。上级提供约215k app/约290k benchmark只是既有功能片段、尚未整合真camera/BLE，不能当最终最大镜像。当前不修改分区、固件或用户离线记录要求。

### 2.3 整笔外径：为什么不能说MINI15.4mm就装得下19mm

当前机械主板基准是B面Y=2.2647931763、厚度上界.93，F面Y=3.1947931763；见机械`compact_contact_cassette_2356/build_cad.py:83`，RevC上下文继承该平面。名义native板厚.83不应代替机械上界。模块最大宽15.6已超过当前14mm板，完整land、承托及装配可达须重查，不能仅让壳体包住悬边就当PCB可贴。

沿用机械`width14_gate/README.md:17`的**条件筛选预算**：1.2mm壳壁+.1壁厚误差+.2装配/弯曲+.1剩余间隙，每侧共1.6；19mm对应可代表半径7.9。以下只是保守长方体包络数值，不是最终STEP实体、选定外径或所有姿态的数学不可能性证明：

| 明确条件 | 条件外径屏幕结果mm | 可以/不可以推断 |
|---|---:|---|
| MINI居中X、直接放当前F平面，max高2.55+.15假设焊接高度 | **22.754** | 同当前叠放位置明显不能按19通过；不能自动批准22.75 |
| 仅模组最大15.6×2.55截面、理想重新居中，不含PCB | 19.007 | 包络已几乎耗尽19；不是整机可装证据 |

| WROOM仅18×3.1名义本体矩形、理想居中 | 21.465 | 同一壳壁预算下不是当前19分支的便捷替代；尚未加公差/PCB |

重新摆放、轴向错开电源、调整手握段形状可能改变结果；须包含笔芯、cassette、电池、连接器、天线禁布、线束与固定后由lead/用户选取尺寸体验，不在本报告暗改边界。小模块并不能自动省层：官方[PCB布局指南](https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/pcb-layout-design.html)给4层优选及受约束的2层示例，且模块/天线有净空要求；这不证明当前多路DVP窄长载板可从6层直接改2层。层数和单/双面SMT是两个不同决定。

## 3. 安全简化只保留一个真实候选，不与MCU改版绑成大重做

候选为**BQ25170DSGR + TDK B57371V2103H060 + 保留合格3.3V稳压与受保护电池 + 插电时硬件停写/隔离大负载**。不是现板替换命令。

事实基线：[既有架构复盘](../power_architecture_tradeoff/README.md)原core23板上实体/2IC/1NTC、12×35；现板50实体/8IC/2NTC、14×45。增量27实体/6IC主要为独立许可/温控链，不能把50件全部说成“充电芯片必需”。当前6个增量IC中的5颗实例已核国内价合计100.86元/两支（未含TPS3808与被动件），说明此处有研究价值，**不是可直接省100.86元**。

[高βNTC研究](../high_beta_ntc_followup_20261028/README.md)已用官方完整R/T min/max表得到该精确TDK型号配BQ25170静态冷停[2,9]°C、热停[36,44]°C，保证恢复窗12–33°C；45°C电气裕量9.721mV。只适合允许0–45类电池边界研究，不适合最低10°C才可充的电池。实际贴附温差、老化、漏电、自热、动态滞后会占用剩余裕量，不因计算过就宣布安全。

[TI BQ25170 Rev A](https://www.ti.com/lit/ds/symlink/bq25170.pdf)为单OUT充电器、无独立SYS powerpath，2×2 WSON；与电池并联的系统负载会分走充电电流并影响终止。模块仍需3.0–3.6V，不能直接接4.2V电池；**保留TPS63802或另经验证的buck-boost监管功能，不把换charger视作稳压消失**。CV/充电电流/输入总限流/安全计时、UV/启动/关断、短路/过压/过放、USB反灌仍各自独立闭环。

最小验证路线（先纸面门，再才可能批准新源）：
1. 选定真实可买受保护pack，其温区/CV/充电与放电峰值/保护阈值明确；保留PCM，不能让TS替代电芯保护。
2. 风险评估决定是否需独立故障后热切断。单NTC/charger的失效覆盖低于双链；若风险要求独立通道，保留通道或否决此简化，不能靠“用户没要求双NTC”省掉安全。
3. 默认安全的硬件充电停写/负载断开，MCU复位/死机/高阻不起作用；USB数据、调试及相机/照明旁路不能偷偷供电；验证NTC开短路/脱离但仍电连续、线阻漏流和控制失效。
4. 计算并实测终止、电池温升和壳温、最坏插拔、各电源序列、输入电流及3.3V动态，随后才谈完整BOM/实际面别/面积。不得承诺退回23件或单面2层。
