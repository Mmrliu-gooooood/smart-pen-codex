# 状态侧车 R2：别名与失败初始化独立复核

2026-11-07。**HOST ONLY / NOT ADOPTED / NOFAB / NOPOWER。**

## 结论

本轮未发现新的阻断问题。R1 的 out=&watch.previous 缺陷，以及失败初始化/重初始化后不得写坏旧 store 或读取未初始化 store 指针的边界，已由 R2 的前置检查和明确错误合同覆盖。

可据此关闭先前的侧车别名合同发现，但结论仅限当前已测宿主软件范围。不表示生产 actor 已接入、硬件已实现，也不替代 ESP-IDF 目标编译和平台验证。

## 1. 修复与错误路径

- activity_status.c:20、80 在任何 store 指针读取、输出清零或 watch 更新之前，拒绝非 NULL 且 initialized!=1 的 app。真实 pen_app_init 失败会先把 initialized 设为 0；首次失败时其余字段可能未初始化，重初始化失败时则可能保留旧 store。两个情形现在都直接返回，不读后续字段、不写任何输出。
- 第 21 行拒绝 get 输出与 app/store 重叠；第 83–87 行拒绝 poll 的 watch/out/changes 相互重叠，以及与 app/store 重叠。检测在第 88–89 行清输出之前完成，因此 R1 中被清掉的比较基线得到保留。
- 重叠或无效 app 生命周期返回 -1，所有对象不写。其他合法独立缓冲区中的普通错误返回 -1，清空已提供的 out/changes、保留 watch。头文件已经明确这两类行为，解决了“既清别名输出又保留 watch”的不可能同时满足的旧合同。
- 非零返回时 out 可能仍含旧 READY/TRACKING，changes 也可能保留旧值。调用者必须先检查返回码，不能依赖所有错误都会清零；当前新合同已明确提醒。合法独立输出调用的成功路径与变化掩码不变。

## 2. 内存范围与未定义行为审查

overlaps 使用 uintptr_t 表示地址，先按整数大小决定减法方向，再比较差值和长度；没有计算可能溢出的区间末地址，没有对无关 C 对象的指针直接做关系比较或减法。当前调用中的 sizeof 长度都为非零。

这是依赖平台地址表示的实现，不是对所有 ISO C 实现的可移植证明。指针到 uintptr_t 的地址排序假设须由目标平台保证，R2 文档已写明平坦地址假设。宿主验证通过；本轮没有 ESP-IDF 目标构建。非 NULL 参数仍必须指向声明类型的有效对象，函数不能安全探测任意坏指针。并发仍要求同一 actor 串行调用，范围检查不提供线程同步。

独立测试直接包含实际侧车源码，调用它的原 private overlaps 函数，并以小整数偏移公式独立计算期望结果。每次执行比较 **802,816 组**真实缓冲区内的双向范围，包含完整包含、部分相交、相同起点、精确相邻和不相交；没有伪造高位指针，也没有让错误类型对象被实际解引用。

另用有声明且对齐的 union 成员构造双向部分重叠，验证拒绝前后完整对象字节不变；用 struct 中相邻的 app/store/watch/out/changes 验证合法相邻对象不会误拒绝。

ASan+UBSan 测试均未报告问题。ASan 设置 detect_leaks=0，本轮不声称泄漏检查通过。MemorySanitizer 不可用，因此“不读取失败初始化后的 store”的判断同时依赖源代码控制流审查，不能误称 ASan 证明了所有未初始化读取均不存在。
